# Product backlog

Use one row per actionable item. Priorities are **P0 (blocking)**, **P1 (important)**, **P2 (later)**. Do not schedule more work just to fill the table.

Status choices: **Proposed / Approved / In progress / Blocked / Done / Deferred / Rejected**.

## How to handle a new request

1. Look for an existing related item or feature before adding a duplicate.
2. Forecast briefly: benefit, dependencies, risk, current foundation, and **PROCEED / ADJUST / DEFER**.
3. Ask for approval before significant implementation; mark the item approved only after a real decision.
4. Record the accepted result and link a relevant Git commit/issue when one exists.

Bug reports should include reproduction evidence; do not invent completion dates or mark a request Done based solely on AI confidence.
